# 首轮协作任务

这些任务可以并行开展，尚未分配负责人。先统一一份小场景及接口，再根据实际开发速度估算排期。

| 任务 | 首个交付 | 验收方式 |
| --- | --- | --- |
| 统一场景契约 | 明确单位、坐标、物品 ID、层板、尺寸来源、可移动性和版本字段 | 同一场景由规划与三维模块读取后含义一致 |
| 感知与几何 | 照片到可人工修正的物品候选；关键尺寸可手工输入 | 保留遮挡、漏检、同款物品等反例，记录修正时间 |
| 规划基线 | 人工真值场景的贪心方案、CP-SAT 对照与独立几何检查 | 检验超大物品、固定物品、重叠、入口限制和超时状态 |
| 三维交互 | 同场景的当前布局与建议布局，可选择物品并查看尺寸 | 尺度一致；拖拽只改草稿，不直接写入真实库存 |
| 库存与集成 | 登记、取用、归还和更正接口；带版本和操作记录 | 重复请求不重复扣减，失败事务不留下半完成状态 |

第一轮不要急于训练新模型或购买硬件。先回答：哪些误差真正导致放不下、拿不出或需要反复修正？

## 首次联调的成功标准

同一份人工核验场景能够产生建议布局，在三维界面看到结果，并在用户实际执行后记录新位置。若暂用 Mock，必须在界面和接口中明确标记。

## 下一轮才决定的增强

- 识别效果是否足以降低手工登记成本。
- 深度设备是否降低关键尺寸误差与采集时间。
- CP-SAT 相对贪心是否在同预算下改善可行率或拿取成本。
- ALNS 相对单独 CP-SAT 是否有稳定且可复现的收益。
- 自动取还识别省下的操作是否多于纠错成本。
