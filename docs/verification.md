新增能力：`Shelf.columns` / `Shelf.divider` 表示一层被竖向隔板分成的格子，`Placement.column` 指明格子序号且 `x` 改为格子内偏移；`geometry.compartment_spans` 用 `divmod` 均分并把余数给左侧格子；`fits()` 与 `overlaps()` 按格子隔离；贪婪规划按 (层, 格子) 遍历。新增 `POST /api/scene/structure`，由外部尺寸与层列数推导柜体骨架；前端增加「结构建模」表单并渲染竖向隔板。

保留的限制：

- **结构接口不落库，只做预览。** 它没有 `request_id` / `expected_version` 语义，直接写库会绕过现有乐观并发模型。因此前端在预览态禁用了「生成布局建议」，避免对旧库存场景出计划；点「刷新场景」恢复持久化数据。
- **竖向隔板的 3D 渲染未经肉眼验证。** 本次只有 `tsc --noEmit`、Vitest 坐标断言和 Vite 构建通过，没有浏览器截图核对隔板位置与配色。前端坐标算法与后端 `compartment_spans` 是同一套 `divmod` 逻辑，但两者一致性只由测试保证，不由目视保证。
- **格子宽度分配用整除**，余数给左侧，因此两列柜在层宽为奇数时会差 1 mm；这是刻意的确定性行为，不是误差。
- 柜体结构仍**只能手动输入**。自动从照片或点云提取层板与隔板尚未实现：点云里层板前边缘只占约 1.6% 的点，且背板/窗帘/桌面等大平面会主导平面拟合；图像路线能测出层板行距（三张照片 251/296/247 px，变异系数 8.5%），但无法区分层板边缘与平放纸张边缘。

本次把上一版"结构预览是死胡同"补齐：`scenes` 表 + 唯一部分索引保证单一活动场景，旧 `scene` 表作为只读历史一次性迁移；`POST /api/scenes` 由结构参数新建**非活动**场景并复制活动场景的在库物品重新摆放，`POST /api/scenes/activate` 显式切换。上一版的无状态预览接口 `POST /api/scene/structure` 已删除，不留两套路径。

升级路径做过验证：用本机 `data/local/storage.sqlite3` 的副本执行 `initialize()`，活动场景仍是原 `demo-room`（版本未被重置）、6 件物品完好、旧 `scene` 行原样、`scenes` 中该行 `active=1`。

保留的限制：

- **场景预览态不能规划、不能写。** 规划只作用于活动场景，所以浏览非活动场景时按钮禁用，必须先「切换到此场景」。这里否决了"点生成建议时自动切换"的做法：那会让一个读语义的操作隐式改动活动场景，属于难排查的状态漂移。
- **物品复制口径**：只复制 `status == "stored"` 的物品，已取出的留在原场景；新柜体没有旧物理位置，试排时忽略锁定，复制出的记录保留原字段；摆不下的丢弃并在 `skipped_item_ids` 返回，原场景不受影响。
- **场景库的 3D 与交互仍未肉眼验证。** 前端只有 `tsc --noEmit`、Vitest 坐标断言和 Vite 构建通过；场景卡片、切换、预览高亮都没有浏览器截图核对。
- **无并发压力测试**：`activate` 的幂等与版本校验有单测，但没验证两个客户端同时激活时的行为；SQLite `BEGIN IMMEDIATE` 与唯一部分索引是目前的全部保障。
- **仍无物品录入**：新场景的物品来自复制，视觉识别/手动新增尚未实现，所以"真实物品进新柜体"这条链仍不完整。
