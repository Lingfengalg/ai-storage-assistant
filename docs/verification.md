新增能力：`Shelf.columns` / `Shelf.divider` 表示一层被竖向隔板分成的格子，`Placement.column` 指明格子序号且 `x` 改为格子内偏移；`geometry.compartment_spans` 用 `divmod` 均分并把余数给左侧格子；`fits()` 与 `overlaps()` 按格子隔离；贪婪规划按 (层, 格子) 遍历。新增 `POST /api/scene/structure`，由外部尺寸与层列数推导柜体骨架；前端增加「结构建模」表单并渲染竖向隔板。

保留的限制：

- **结构接口不落库，只做预览。** 它没有 `request_id` / `expected_version` 语义，直接写库会绕过现有乐观并发模型。因此前端在预览态禁用了「生成布局建议」，避免对旧库存场景出计划；点「刷新场景」恢复持久化数据。
- **竖向隔板的 3D 渲染未经肉眼验证。** 本次只有 `tsc --noEmit`、Vitest 坐标断言和 Vite 构建通过，没有浏览器截图核对隔板位置与配色。前端坐标算法与后端 `compartment_spans` 是同一套 `divmod` 逻辑，但两者一致性只由测试保证，不由目视保证。
- **格子宽度分配用整除**，余数给左侧，因此两列柜在层宽为奇数时会差 1 mm；这是刻意的确定性行为，不是误差。
- 柜体结构仍**只能手动输入**。自动从照片或点云提取层板与隔板尚未实现：点云里层板前边缘只占约 1.6% 的点，且背板/窗帘/桌面等大平面会主导平面拟合；图像路线能测出层板行距（三张照片 251/296/247 px，变异系数 8.5%），但无法区分层板边缘与平放纸张边缘。
