# AI 收纳辅助系统

通过拍照识物、空间建模和约束规划，为用户提供放得下、拿得出、少搬动的收纳建议，并通过三维预览与取还记录保持物品位置可查。

**当前状态：已有可运行的本地研发框架，不是完整产品。** 包含合成场景、三维预览、贪心规划基线和持久化库存操作；尚未接入视觉模型、CP-SAT 或深度硬件，不代表已获立项。

## 先运行起来

参阅 [开发启动说明](docs/development.md) 安装依赖，然后运行 `scripts/dev.ps1`，访问 `http://127.0.0.1:5173`。

已安装环境也可在两个终端分别运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
npm --prefix frontend run dev
```

## 首版范围

- 场景：桌面与有固定层板的柜体，约 20–30 件刚性日用品。
- 识别：照片产生物品候选，用户确认类别、尺寸、位置和可移动性。
- 规划：一层多物品、有限朝向，先解决多层平面布局与高度限制，不支持自由堆叠。
- 展示：用真实尺度的简化几何体展示当前布局与建议布局。
- 库存：登记、取用、归还、查找与更正；建议布局不直接修改真实库存。
- 可选：深度传感器、购买前空间适配与功能重复分析、置物架推荐。

购物推荐不是主功能；整屋重建、无人确认库存、强化学习与复杂堆叠不列为首版前置条件。

## 技术方向

| 方向 | 候选实现 | 人需要理解的重点 |
| --- | --- | --- |
| 感知与几何 | 预训练检测/分割；RGB-D 与 Open3D 按需评测 | 尺度、标定、坐标变换、遮挡与误差 |
| 收纳规划 | 贪心基线、候选位置、OR-Tools CP-SAT | 硬/软约束、可行性、拿取路径、求解状态 |
| 三维交互 | 浏览器端 Three.js | 几何尺度、坐标、选择和确认流程 |
| 库存与集成 | Python、FastAPI、SQLite | 事务、幂等、版本与状态一致性 |

技术选择以实验为准；ALNS 和额外硬件不默认加入。AI 可以搭建代码，但不能代替独立验证。

## 三个验收节点

1. 同一份人工核验场景贯通规划、三维展示和库存接口。
2. 接入真实照片与确认流程，完成真实摆放、取用和归还。
3. 用基线、失败案例与同条件对照实验决定哪些增强值得保留。

这些是结果检查点，不是需要依次完成的学习课程；四个方向可并行推进。

## 仓库内容与数据

- `docs/`：技术说明与首轮任务。
- `backend/`：FastAPI、领域模型、几何检查、贪心规划、SQLite 与测试。
- `frontend/`：React、TypeScript、Three.js 空间工作台。
- `shared/`：OpenAPI 契约；前端类型由它生成。
- `scripts/`：本地启动脚本。
- `.github/`：Issue 和 Pull Request 模板。
- `CONTRIBUTING.md`：协作与验收规范。

仓库 CI 检查后端、契约、前端坐标测试与构建。首个演示场景仅使用 6 件合成物品；20–30 件真实物品仍是后续验证目标。
不提交密钥、真实室内照片、个人物品数据库、模型权重或历史获奖名单；使用合成样例或取得授权并脱敏的数据。
